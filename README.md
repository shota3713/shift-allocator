# シフト振り分け

勤務（予定）表のPDFを読み取り、確定した勤務日の枠に業務（リハ担当・入浴・レクなど）を
公平に割り振るスマホ向けウェブアプリ。サーバーを持たない静的サイトで、GitHub Pages で動く。

読み取りは端末の中だけで完結する。PDFも氏名も外へ送らない。

## 使い方

毎月やるのは3つだけ。上から順にやれば終わる。

1. **勤務表を読み込む** — PDFを選ぶ。その場で読み取る
2. **確認して確定する** — 人×日の表を原本と見比べる。赤い欄があれば直す
3. **業務を割り振る** — 実行する。担当を手で変えると「今後も反映しますか？」と聞く

初回だけ、名簿と勤務区分が自動でできる。担当者を限定したい業務（連絡帳など）は
設定で指定する。

## 読み取りについて

この帳票はテキストレイヤ付きで、日付ヘッダも氏名列も同じ位置に揃っている。
だから読み取りに推論は要らない。**列は日付ヘッダの座標から、行は氏名の座標から決まる。**

- OCR も AI も使わない。同じPDFからは毎回まったく同じ結果が出る
- 形に合わないセルは埋めずに「読めなかった」として残し、人に直させる
- 1件でも未解決が残っていれば確定できない

実データ（22人 × 30日 = 660セル）で、Python の決定論パーサが出した結果と
氏名・職種・勤務区分・業務メモ・年月まで完全に一致することを確認している
（`tests/shiftTable.test.ts` が同じ座標データで回帰を見張っている）。

### 前提にしている帳票の形

次の条件を満たすPDFを想定している。崩れると「読めなかった」として人に回る。

| 前提 | 内容 |
|---|---|
| テキストレイヤ | スキャン画像ではなく、文字として埋め込まれていること |
| 日付ヘッダ | `01` `02` … が横一列に並ぶこと |
| 見出し | `チーム名` `氏名` `職種` の3つがあること |
| 勤務区分コード | `日_032DS` のように、末尾が `_数字3桁 + DS/SS` で終わること |
| ページまたぎ | ページごとにヘッダが繰り返されること |

コードの形は [`src/pdf/codeSplit.ts`](src/pdf/codeSplit.ts) の1か所に書いてある。

## データの置き場所

- 名簿・取り込み結果・振り分け・学習ルールは、**開いた端末のブラウザ（localStorage）にだけ**保存される
- 別の端末で使うときは「設定 → データ」でバックアップを書き出し、向こうで読み込む
- リポジトリには実名や勤務データを一切含めない（`tests/fixtures/` は氏名を差し替えた座標データ）

## 振り分けの考え方

**ハード制約（絶対に破らない。手修正でも破れない）**

- 出勤していない日には割り当てない
- 担当できる職種・指名された人だけ
- 同じ時間帯（午前・昼・午後）に1人1業務
- リーダー系の業務（入浴リーダー・連絡帳・レクリーダー）は同じ日に同じ人が兼任しない

**ソフト制約（均等にする）**

- 負担も業務ごとの回数も「出勤1日あたり」で揃える。出勤日数の違う人を生の回数で
  揃えると不公平になるため
- 学習したルール（「この人はこの業務を避ける」など）を反映

同じ入力・同じ設定・同じ seed なら結果は毎回同じになる。学習の効果を比べられるようにするため。

実行前に、時間帯ごとの最大マッチングで「そもそも埋まらない枠」を診断して表示する。
頭数だけでは足りない（午前6枠に6人いても、2人が看護職員で看護師枠が1つしかなければ1枠余る）。

## 学習

担当を手で変えても、それだけではルールにならない。画面で選んだものだけがルールになる。
初期値は必ず「今回だけ」にしてある。一度きりの事情が恒久ルールとして積み上がらないため。

同じ修正が過去に何回あったかを提案に添えるので、「たまたま」と「傾向」を目で区別できる。
ルールは設定画面でいつでも無効にできる。

## 構成

```
index.html               Vite の入口
src/
  pdf/                   PDFの読み取り（pdf.js に触るのは loadPdf.ts だけ）
    types.ts             座標付きテキストと、読み取り結果の型
    loadPdf.ts           PDF → 文字と座標
    shiftTable.ts        座標 → 人×日の表
    codeSplit.ts         セル内の文字 → 勤務区分コード + 業務メモ
  core/                  計算。保存層もDOMも知らない
    types.ts             領域モデル
    assign.ts            振り分けエンジン
    feasibility.ts       埋まらない枠の事前診断
    plan.ts              保存データ → 振り分けの前提
    stats.ts             公平性の集計
    learn.ts             手修正と学習
    import.ts            読み取り結果 → 確定データ
    resolve.ts           名寄せ・勤務区分の解決
    masters.ts           マスタの初期値と差分
  store/db.ts            localStorage
  ui/                    画面
  styles/                デザイントークンとスタイル
tests/                   78件
docs/                    GitHub Pages で公開するビルド結果
```

## 開発

```bash
npm install
npm run dev      # http://localhost:5178
npm test         # 78件
npm run build    # 型チェック + docs/ へ出力
```

`local/` を作ってそこに実データを置くと、実PDFとの突き合わせテストも走る
（`local/` は `.gitignore` 済み）。

## GitHub Pages の設定

`npm run build` の結果（`docs/`）をコミットし、リポジトリの Settings → Pages で
Source を「Deploy from a branch」、Branch を `main` / `/docs` にする。
